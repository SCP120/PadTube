# PadTube decisions

The owner approved the plan on 2026-11-11 and said: "do it auto, from start to end, don't ask me". Each decision below was made without a question to the owner. Each line gives the reason.

| # | Date | Decision | Reason |
|---|---|---|---|
| D1 | 2026-11-11 | Name: PadTube. Bundle `dev.padtube.app`. Folder `~/padtube`. C prefix `tb_`, Objective-C prefix `TB`. | PLAN §8 proposal. `pt_` is used by PadTerm. |
| D2 | 2026-11-11 | Own HTTP client on OpenSSL 3.5.9 (copied static armv7 build from PadTerm), not NSURLConnection. | One code path for all hosts. TLS 1.3 + session resumption (iOS 6 has no session tickets, research-efficiency §6). Keep-alive pool under our control. |
| D3 | 2026-11-11 | Trust store: the Mac's `/etc/ssl/cert.pem` copied into the app as `roots.pem`. | OpenSSL needs a CA file. The iOS 6 keychain roots are not readable by OpenSSL. |
| D4 | 2026-11-11 | Phase 0 spike code is written at product quality and becomes the Phase 2 base. Phase 1 documents describe it. | Saves a rewrite. The house rule "document before implementation" holds for Phase 2+ features that the spike did not cover. |
| D5 | 2026-11-11 | Remux: 1 DASH fragment = 1 TS segment. Audio frames go to the segment whose time range holds their DTS. Segment 0 starts at minus infinity. | Research §4.2: every fragment starts with a keyframe. A test found 3 audio frames lost before the first video PTS (B-frame delay); the minus-infinity start keeps every audio frame exactly once. |
| D6 | 2026-11-11 | Audio fetch: first 8 KB of the audio fragment (moof), then only the bytes up to the last sample of the video segment. | 360p start needs 242 KB, not 317 KB, at 130 KB/s (research §4.5). |
| D7 | 2026-11-11 | Auto quality = master playlist with 360p first and 480p second. Manual choice lists every avc1 height up to 720p. No 1080p. | PLAN §2 "start 360p, default 480p, 720p manual". A5 panel is 1024x768. |
| D8 | 2026-11-11 | Own player controls (MPMoviePlayerController, control style None). Own full screen (the view grows to the window). | MPMoviePlayer full screen moves the video to its own window, so our captions would not show. |
| D9 | 2026-11-11 | Captions: `fmt=srv1` (smallest), drawn in a UILabel over the video. | research-features §4.3: 3.6 KB vs 14.8 KB vtt; iOS 6 does not render side-loaded subtitles. |
| D10 | 2026-11-11 | Field masks on search (MWEB). If a mask returns no items, the call repeats without the mask. Watch page, channel and playlist calls have no mask for now. | Masked search: 10.9 KB decoded, 2.4 KB gzip on 2026-11-11 (160 KB without). The fallback keeps the app working when YouTube changes a layout. |
| D11 | 2026-11-11 | Local store: SQLite of iOS 6 (3.7.13), WAL. SQL limited to 3.7.13 features (no UPSERT). | research-efficiency §7. A test on the Mac uses the same SQL. |
| D12 | 2026-11-11 | HLS stream swap does not block: the server holds a reference per request (refcount), a freed stream is marked dead. | A quality change or a new video must not stall the main thread (gate: no stall > 50 ms). |
| D13 | 2026-11-11 | Signed-out Home: videos related to the last video watched on this iPad; a starter search when the history is empty. | The signed-out home feed is empty in 2026 (research-features F8). |
| D14 | 2026-11-11 | The Phase 1 documents are written by a sub-agent from the code and the research, in parallel with device work. | Saves wall time; the documents describe code that exists. |
| D15 | 2026-11-11 | Field mask on the watch page call (next), with the same no-mask fallback as search. | 44 KB -> 4.9 KB gzip, 325 KB -> 15 KB JSON on aircAruvnKk (MEASURED on the Mac). Less radio time and parse time on the A5. |
| D16 | 2026-11-11 | **Owner decision, replaces D7:** default quality 720p. A quality the person picks is saved (NSUserDefaults `TBQuality`) and used for the next videos. "Auto" stays a choice: a master playlist from 720p down, 720p first. Without 720p the player takes the highest height below the choice. | Owner request 2026-11-11. The start gate is measured at 720p on the owner's Wi-Fi (docs/STATUS.md). |
| D17 | 2026-11-11 | **Owner request:** full screen is always landscape. The player moves into a presented controller with `supportedInterfaceOrientations` = landscape and `preferredInterfaceOrientationForPresentation` = the current landscape side (else landscape right). On exit, `attemptRotationToDeviceOrientation`; if the iPad lies flat, the private `-[UIDevice setOrientation:]` restores the orientation from before. | iOS 6 rotates the interface on present for such a controller. A flat iPad has no device orientation to go back to. A private call is acceptable in a personal jailbroken app. |
| D18 | 2026-11-11 | **Owner bug "49-minute video takes forever":** a device regression test (`tests/device/start_long.py`) checks start time and bytes before the first frame for a 3-min, a 56-min and a 64-min video, plus a far seek. | Start must not grow with the video length. |
| D19 | 2026-11-11 | Live: the core merges YouTube's video-only TS and packed-AAC rendition into one TS per segment and serves a live-edge playlist (6 segments) on 127.0.0.1 (`core/tb_live.c`). If the iOS player rejects it, the player gets YouTube's manifest directly. | iOS 6 support for separate audio renditions is unverified (research §6.2). The video and audio playlists share sequence numbers (MEASURED). Merge checked with ffmpeg on a real live stream. |
| D20 | 2026-11-11 | Background audio: keep the video playlist; if iOS pauses it in the background, switch to the audio-only playlist at the same time, and back to video on return. | Research §4.2 known-working fallback (AAC in TS). The switch happens only when the pause is seen, so it costs nothing where iOS keeps playing. |
| D21 | 2026-11-11 | The UIWebView PO-token test (TubeReplacer method) is deferred to after the Tier 1-2 gates. | No Tier 1 feature needs it: VISIONOS plays without a PO token; only auto-translated captions (HTTP 429) need it. |
| D22 | 2026-11-11 | The shared MPMoviePlayerController is made once, 1.5 s after launch. | Creating one costs 224-247 ms on the main thread (MEASURED on the iPad); the stall gate is 50 ms. |
| D23 | 2026-11-11 | The subscriptions feed (TV client) is shown newest first, without repeats. | research-features §4.4: the TV feed is relevance-first and repeats videos across shelves. |
| D24 | 2026-11-11 | TV client lists (signed in) have no field mask for now: 793 KB decoded per channel page, parsed off the main thread. | Masks need the full path of each shelf type; set one when a device measurement shows a cost. |
| D25 | 2026-11-11 | **Owner UI rule:** the UI copies YouTube for iPad 1.x (2012-2013), element by element from `docs/design/old-youtube-ui.md` (15 reference screenshots in `docs/design/reference/`). Header style: 1.x dark header (the owner asked for "the dark/grey header and red accents of that era"); red only as an accent (progress bar, live badge, wordmark bar, sign-in code). Our own drawings and a plain "PadTube" wordmark; no Google logo or icon files. | Owner request 2026-11-11. The 2.x light header (Aug 2013) is not used. |
| D26 | 2026-11-11 | The tab bar is replaced by the 1.x guide (left menu) + one shared header with the search pill. The light/dark switch is removed: the 1.x look has dark chrome and light content only. | The owner UI rule replaces the "stock iOS 6, light + dark" line of the brief. |
| D27 | 2026-11-11 | Portrait watch page: About / Suggested / Comments segments under the player (iPhone 1.1 pattern). | No 1.x iPad portrait reference exists (design doc §8.5); marked "derived". |
| D28 | 2026-11-11 | **Owner bug "login opens a web page":** PadTube has no web view (`grep` of ios/ and core/: no UIWebView, no openURL; a test now keeps it so). The Account screen shows the code in 56 pt, google.com/device and a QR code (Nayuki QR Code generator, MIT, in C: iOS 6 has no CIQRCodeGenerator), and says to use a phone or computer. | The page the owner saw does not come from this app's sign-in path; the request is met either way. |
| D29 | 2026-11-11 | Player engine stays MPMoviePlayerController. AVPlayer is kept as an option (`TBEngine = 1`). | A/B on the iPad: AVPlayer seek stalls the main thread 206-217 ms vs 46-85 ms; starts 0.87-1.67 s vs 0.75-1.40 s; steady playback 19 vs 6 ms. |
| D30 | 2026-11-11 | Stream locking: one lock for builds/downloads, one short lock for refs and prefetch flags; stats are read without a lock. | A stall sampler on the iPad showed the main thread waiting 100-930 ms on the build lock (stats read, HLS swap). |
| D31 | 2026-11-12 | **Owner request:** compact grid (3 tiles portrait, 4 landscape) on Home, Subscriptions, Search, Live, channel and playlist lists; list cards stay for History, Watch Later and Liked (swipe to delete). | No 2012-2013 reference shows a grid (all show feed cards); the owner asked for it after a photo of the wasted space. |
| D32 | 2026-11-12 | **Owner bug "Home duplicates":** de-duplicate by kind + id and, for playlists, by the first video (RD id or thumbnail URL); within one TV page (core, `tb_list_dedupe`) and across pages (list "seen" set). | Captured signed-in Home (10 pages): 125 items, 110 unique. Causes: one video in several shelves of a page; videos repeated on later pages; a mix as a tile and as a lockup. No page was appended twice. |
| D33 | 2026-11-12 | Mixes (RD...) open their queue through `next` (videoId + playlistId); `browse VLRD...` gives no items. Playlists and mixes carry a marker on the tile (dark panel, list icon, count or "Mix") and a red "Mix / Playlist" line. | Owner request; measured on the Mac. |
| D34 | 2026-11-12 | Titles go through an iOS 6 emoji filter (keep Unicode 6.0 emoji, drop newer ones, skin tones, ZWJ, tags). | Owner report: new emoji draw as empty boxes on iOS 6. |
| D35 | 2026-11-12 | App icon: Codex image generation (`codex exec`, the PadTerm recipe), glossy iOS 6 tile with a retro TV and a red play disc, no logo or text; all sizes from `tools/make_app_icons.c`; `UIPrerenderedIcon` (the art has its own gloss). | Owner request (5). |
| D36 | 2026-11-12 | Links in descriptions and comments open in the app with PadWeb (`PWBrowserController`); YouTube watch/shorts/youtu.be/channel links open in PadTube. PadWeb starts at the first link, not at launch. | Owner request; no RAM for PadWeb until a link is used (joint PadBook memory rule). |
| D37 | 2026-11-12 | PadTube self-test ports 5130-5134 with a "whoami" check before "quit"; PadBook uses 5140. | Both apps share the iPad; a quit must never reach PadBook. |
| D38 | 2026-11-12 | App icon = owner-approved option A (`assets/art/v3/a/icon.png`, committed as the one binary source asset). `tools/make_app_icons.c` crops the tile, cuts 18 % transparent rounded corners, 8 sizes, files `PTIcon2*.png` in CFBundleIconFiles and CFBundleIcons, CFBundleVersion 0.1.2. The home screen keeps the blank icon until SpringBoard restarts: I do not reboot or respring (brief), and uninstall + install would delete the sign-in. | Proof that SpringBoard does not reload icons on install on top: PadBook still shows its old icon after its 0.1.1 icon change; PadTube stays blank after two renames (PTIcon, PTIcon2), CFBundleIcons and two version bumps (0.1.1, 0.1.2); the install service reports the new keys (screenshots 01:39, 01:41, 02:07). Same PNG format as PadBook (chunks, sRGB). |
| D39 | 2026-11-12 | Light / Dark theme on the Account screen, saved (`TBDark`), default Light. Dark keeps the 1.x chrome and darkens only the light areas (design §14, DUC-SET-THEME). A change rebuilds the root UI instead of updating each view; all theme colours and images live in `TBStyle`. Replaces the "one style" part of D26. | Owner request 2026-11-12 (full dark mode in the old style). A rebuild needs no per-view update code (less code, no missed views); the cost is that an open watch page closes on a change. |
| D40 | 2026-11-12 | Signed in, a playlist page loads as TV `VL<id>` with the account; with no rows, the signed-out web page. | Owner report: a private playlist opened empty ("Nothing here."): the web client has no account. Measured: a private playlist 0 -> 12 rows; another playlist 20 -> 27 rows. |
| D41 | 2026-11-12 | Subtitles list order: device languages, then English, then the rest by name; manual before auto-generated (`tb_caps_sort`, in C with a golden test). Captions still start Off. | Owner report: Arabic came first (YouTube's order). |
| D42 | 2026-11-12 | Playback speed is cut: no Speed button. | Measured on the iPad: rate 1.5 gave 6.01 s (MediaPlayer) and 6.02 s (AVPlayer) of video in 6 s with our local HLS stream (`followups.py`); earlier 4.01 s in 4 s (`tier2.json`). A control that does nothing fails the brief's rule. |
| D43 | 2026-11-12 | No [PadWeb prewarm]: PadWeb (WebKit) starts at the first web link. | Measured: the first link has one 88 ms main pass, a later link 31 ms; prewarm removes 44-66 ms of it but costs about 3 MB that stays (PadWeb session, PadWebDemo 13.9 -> 16.9 MB) and runs on the main thread at a time the owner may be scrolling. A pass during the browser's open transition is less visible than one in a scroll, and the RAM stays free for PadBook next to PadTube. |
| D44 | 2026-11-12 | PadTube is released in public on GitHub (`SCP120/PadTube`), MIT, holder "PadTube contributors". This replaces "personal use, never published". Plan: `docs/release.md`. | Owner order 2026-11-12. Same holder and licence as PadTerm. Vendored code is MIT (yyjson, qrcodegen), Apache-2.0 (OpenSSL) or ISC/Unlicense (JS helper, self-test only); none forbids MIT. |
| D45 | 2026-11-12 | The public repository gets an export of the tracked tree (`scripts/export_public.sh`), one commit per release, not the private history. | The private history holds owner reports, test logs and files that the export leaves out (`docs/release.md` §2). One tree is easier to check than 56 commits. |
| D46 | 2026-11-12 | PadWeb is optional at build time. `PUBLIC=1`, or no `~/padweb`: no PadWeb, web links open in Safari. The owner's build keeps PadWeb. | PadWeb is private (no remote, no licence), so a public build cannot link it. Safari is the only browser left on a stock iPad; on iOS 6 it fails on some modern sites. |
| D47 | 2026-11-12 | Public icon: an old TV set on a teal tile, drawn by code (`tools/make_public_icon.c`). Option A (red rounded tile, white play triangle) stays only in the owner's build (`assets/icons/owner/`, not published). | Option A is close to Google's YouTube logo: same red rounded tile and white play triangle. A public app must not be confusable with it. |
| D48 | 2026-11-12 | Release assets: rootful `.deb` (armv7 + arm64, iOS 6 to 14), rootless `.deb` (arm64, iOS 15+), sideload `.ipa` (armv7 + arm64, iOS 7+), `SHA256SUMS.txt`. arm64 minimum iOS 7.0. Release `v0.1.0` is a pre-release. | Owner order: iOS 6 and up. Only armv7 on iOS 6.1.3 can run on our one device; arm64 is built and checked on the Mac only, so the release is a pre-release, as PadTerm's. |
